# AI News 公开访问与抓取策略

更新：2026-10-10
适用范围：`gyread.com/news`、AI News 英文站、图片 COS 与 GitHub 公开源仓。

## 结论

AI News 保持公开可读，搜索与正常引用放行。
不做“全民封爬虫”的假防护，因为它挡不住恶意抓取，还会损失自然流量。
真正的成本控制放在静态 CDN、图片缓存、带宽监控和异常限流上。

## 三层策略

1. **内容层：允许被发现**
   - 搜索引擎、普通读者和 RSS 阅读器可以访问。
   - 站点保留规范链接、署名和一手来源。
   - `robots.txt` 只屏蔽 `.bak`、脚本、测试、构建目录等非正文文件。

2. **机器层：表达训练边界**
   - `Content-Signal: search=yes, ai-input=yes, ai-train=no`。
   - 机器可以读取并引用页面，默认不把整站内容当作训练语料。
   - 这是公开偏好信号，不是技术封锁，也不能保证所有爬虫遵守。

3. **基础设施层：控制实际成本**
   - 页面由静态站或 CDN 提供，不依赖单台动态服务器。
   - 图片放在对象存储与 CDN 后面，长期缓存，按响应式尺寸输出。
   - RSS 只提供标题、短摘要和链接，不提供全文。
   - 先监测最近 14 天的日流量 P95，异常线按 P95 的 3 倍告警。
   - 只有出现持续滥用时，才对具体 IP、ASN 或路径加 Cloudflare 限速。

## 为什么不能靠 GitHub 私有或仓库封闭解决

公开仓库可以被克隆，网页浏览器也可以保存全文。
把内容放上互联网之后，绝对防抄无法做到。
可以控制的是署名、规范链接、转载边界，以及让正常读者访问得更快。

因此：

- GitHub 可以继续作为公开源仓和审阅通道。
- 网站仍是正式发布入口。
- 全量镜像、批量转载、商业再分发需要单独授权。
- 发现抄袭时保留规范链接、时间戳和提交记录作为证据。

## 上线检查

- [ ] `robots.txt` 已在域名根路径提供，并且策略与仓库一致。
- [ ] `sitemap.xml` 可通过规范域名访问。
- [ ] 中英文 RSS 均返回有效 XML。
- [ ] 图片响应包含长期缓存头。
- [ ] 已建立带宽与 5xx 告警，不用人工每天盯。
- [ ] 出现滥用后再加限速，先动具体异常，不封正常读者。

## 部署边界

本仓库内的 `robots.txt` 是源文件。
`gyread.com` 主机级 `robots.txt` 仍需主站部署路径提供。
`/news/robots.txt` 不等于主机级规则，主流爬虫仍会读取域名根目录。

## 判定口径

公开可读不等于放弃版权。
仓库 public 不等于授权全文转载。
Content-Signal 不等于技术封锁。
真正的服务稳定依靠 CDN 与缓存，不依靠喊话式反爬。
