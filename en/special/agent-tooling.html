Agent Tool Revolution:
From 'Chatting' to 'Doing'
2026-06 → 08 · Special 30+ Reports · 1 Core Theme
In the first half of the year, Agents were still just 'models that could chat'.

This summer, they are starting to actually do the work: MCP turns tool integration into a single request, Claude Code can run inside enterprise intranets, small local models run Agents on smartphones, and following the disbandment of DeepMind's AlphaFold team, talent is flowing toward AI for Science Agents.

The chatbox is turning into a workbench, and Agents are shifting from 'conversations' to 'colleagues'.
Read This First · Plain English Version

Three plain-English takeaways:
First, AI has shifted from 'answering questions' to 'doing the work for humans', capable of calling software, searching data, and operating computers on its own, like hiring a digital assistant, only cheaper and faster.
Second, these capabilities are 'integrating into your daily tools', with WeChat, enterprise software, and coding tools all plugging in—you might already be using them without realizing they are AI Agents.
Third, the boundaries of 'doing the work' are tightening, as the tasks it can handle expand alongside debates over whether it should handle them, making security the new threshold.

Terminology Plain-English Cheat Sheet:

Agent ≈ An AI that can independently 'plan steps, call tools, and do the work,' completing tasks on its own like an employee.

MCP (Model Context Protocol) ≈ A 'standardized socket' for connecting AI to tools; with it, integrating any software is as simple as plugging it in.

Local Deployment / Self-Hosting ≈ Run AI on your own computer or server, keeping data local and privacy under control.

Stateless ≈ No need to "greet and establish a connection" before every task—a single request gets straight to work, making it faster and more efficient.

DEEP DIVE
What Happened in the Summer of Agents
I. From "Conversation" to "Workflow"

In the first half of the year, agents were imagined around "conversation": answering questions, writing code, and generating images. This summer, the focus shifted to "execution": calling tools, accessing enterprise internal networks, and running autonomously overnight.

A landmark change is statelessness in MCP 2.0: tool integration shifted from "handshake then call" to "a single HTTP request." While this seems like a minor protocol tweak, it reduces the cost of connecting tools to agents by an order of magnitude.When connecting tools is as simple as calling an API, agents are no longer lab toys, but components that can be embedded into any system.。

II. Where Are the Boundaries: Meat Proxy and Self-Hosting

As agents grow stronger, humans are redrawing boundaries. Niklas Gruhn's meat proxy reminds us: don't forward AI output blindly—that's not using AI, that's acting as a repeater. David Crawshaw's overnight rebase showcases the flip side: mechanical maintenance work should indeed be handed over to agents.

Anthropic's two-step move is even more representative: first, Inference Hooks allows enterprises to intercept before inference, and second, self-hosted Claude Code lets sessions run inside enterprise internal networks.Between "AI that works" and "AI that enterprises dare to use" lies a floodgate controlled entirely by companies themselves.。

III. Localization: The Next Stop for Agents

Liquid AI's 2.6B model can run Agents on phones and in browsers; combined with MCP's local tool integration,"Agents that work offline" are taking shape. For privacy-sensitive, unstable network, and zero-data-leakage scenarios, local Agents are the only solution.

Signals in this direction are already abundant: Microsoft Aion running Agents locally, Apple system models, and LLM 0.32 local logs.The Agent battlefield is shifting from "whose model is smarter" to "whose Agent can truly run on users' own devices."。
